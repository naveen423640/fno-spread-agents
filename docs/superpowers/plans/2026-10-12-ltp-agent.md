# LTP Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sub-tab "LTP Agent" inside the LTP tab: a deterministic, paper-only agent that trades the LTP rules on NIFTY, BANKNIFTY and SENSEX in two books (BUY and hedged SELL), journals every decision at decision time, has an LLM review closed trades, and after 100 trades tests LLM-proposed rule changes on held-out days behind a gate and my approval.

**Architecture:** One pure function `agentStep(ctx, underlying, ts)` reads the stored snapshots up to `ts` (never the future), runs the existing `analyzeSession`, evaluates a versioned strategy and returns decisions plus trade actions. The live runner calls it once per recorded minute; replay calls it for every stored minute of a day, so live and replay are the same code path. Decisions are append-only; outcomes and reviews are separate tables. The LLM sits outside the loop (reviewer and proposer only) and can touch only schema-listed tunable fields within bounds.

**Tech Stack:** TypeScript, vitest, zod 4 (already installed), D1/SQLite via drizzle migrations, `lib/llm` client for the reviewer, `yaml` (new dependency, see decision 1), lightweight-charts and the existing UI components.

**Spec:** the task brief "LTP Agent" pasted in the conversation of 2026-10-12 (sections A to G, "Hard rules", "How to work"). Section letters below refer to it.

## What the exploration found (about 15 lines)

1. **Engine:** `lib/ltp/analyze.ts` `analyzeSession(snapshots, {now, method})` is the "ltp_engine_state": levels, per-metric weakness %, side directions/events, COA 1.0 scenario (from directions) with hit counters, COA 2.0 trends and outcome, SOC, diversions, 9:20 lines (`lines0920.ts`), live extensions (EOS/EOR family), weekly range (`weekly.ts`). Pure, takes `now`.
2. **Store:** `lib/ltp/store.ts` (D1, snapshots in long format, minute-floored `snapshot_ts`, gaps table). `buildState` in `lib/ltp/state.ts` builds the tab payload.
3. **Bid and ask exist in the FYERS chain but we throw them away.** `parseChain` keeps only ltp/oi/volume, and the index leg's `fp` (futures price) is dropped too. Every stored snapshot so far has no bid/ask, so every historical fill would be `ltp_fallback`. Task 0 fixes capture going forward; older days stay flagged.
4. **No scheduler.** The app has no cron. `scripts/ltp-recorder.ts` is a loop that POSTs to the running app each minute; the agent runner follows the same pattern.
5. **LLM:** `lib/llm` (`createLlmClient`, providers from env, `ANTHROPIC_API_KEY` already in the default Anthropic entry, replay client for tests). Reused for the reviewer.
6. **Costs:** `lib/options-costs.ts` has dated STT and exchange rates for payoff estimates. The agent needs its own dated config and a paise-exact calculator (Task 2) and will cross-check against it.
7. **Safety:** `tests/safety/no-order-endpoints.test.ts` scans `lib/app/scripts` for order terms; the agent adds its own import guard.
8. **Not present:** `strategies/`, `experiments/`, a YAML parser, lot-size history (the tab hardcodes 65/30/20 for display only), a futures price series.
9. **UI:** `app/ltp-tab.tsx` is a single-screen tab with a panel switcher; the Agent tab becomes a second sub-tab beside it.
10. **Real data so far:** one live session (2026-10-12, recorder started 09:47). The 100-trade journal phase will take weeks of live recording.

## Decisions that need your approval before any code

1. **TypeScript, not Python.** pydantic becomes zod, dataclasses become types, YAML needs the `yaml` npm package (the only new dependency). `agent-replay`, `agent-review`, `experiment-run`, `report` become `npm run` scripts with those names.
2. **Task 0 changes the recorder first:** add `bid`, `ask` to `ltp_snapshots` and a futures-price column (migration 0009). Until bid/ask exist for a day, that day's fills are `ltp_fallback` and flagged. This is the only change to existing recorder data paths; it is additive.
3. **Scheduler = one runner script** `scripts/ltp-agent.ts run` (same style as the recorder): steps the agent after each recorded minute, runs the daily review at 15:35 IST, weekly summary and proposals on Friday after the daily review, monthly report on the first trading day. Needs the app running, like the recorder.
4. **Entry levels per setup (my reading of A):** `coa1_reversal` trades the scenario's own listed level when it is not the primary one (EOS-1, WTB+1, WTT-1, EOR+1, from the COA table), otherwise EOS/EOR (`risky`) or EOS-1/EOR+1 (`moderate`). `nine_twenty` uses the frozen 9:20 lines as rebuilt (Risky and Moderate). `end_of_diversion` ships disabled and unimplemented because the engine does not specify a trade rule for it; the flag exists so a later version can add it.
5. **Target and stop:** target = the opposite extension of the live pair (EOS for shorts, EOR for longs, the tool's "Max Gain"), also when the course lists the other end as N/A. Stop = Max Pain level (EOR+2 / EOS-2) plus/minus `stop_buffer_pts` (default 10), or the next reversal beyond entry plus buffer when `stop_rule` is `next_level`.
6. **BUY book strike:** ATM (nearest strike to spot at entry) or 1-OTM. **SELL book:** short leg at the support (long signal) or resistance (short signal) strike, hedge `hedge_width` strikes further out (default 4).
7. **Tick and fallback defaults** (config, not code): tick 0.05, `slippage_ticks` 1, `fallback_slippage_pct` 2.0; margin estimate = spread width x lot size - credit, labelled an estimate.
8. **"Hit number"** uses the engine's existing touch counter (`coa1.hits`), which counts approaches within 5 points per day.
9. **Replay of a late-started day** cannot reproduce side directions from 09:15 (the engine reads history). Such days are replayed as recorded and every decision carries `data_quality.history_from` so they can be excluded from learning.

## Global Constraints

- PAPER ONLY. `lib/ltp-agent/**` and `scripts/ltp-agent.ts` import nothing that places, modifies or cancels orders; a test scans their imports and source for order terms and FYERS order modules (Task 1).
- Claude never decides trades. The rule engine plus the strategy file decides; the LLM only reviews and proposes, and every result is reproducible by replay.
- "No trade" is always valid. No reward for activity; the gate compares to "no trade" (Rs 0).
- Never fabricate data. Missing bid/ask or a missed snapshot is flagged on the trade (`fill_quality`, `data_quality`), never filled in silently.
- Secrets: LLM keys only through `lib/llm` env handling (`ANTHROPIC_API_KEY`); never logged, committed or put in a journal row.
- Strategies live in `strategies/ltp_vX.Y.yaml`, validated by a zod schema. v0.1 = the pure course rules with the defaults in section A.
- The reviewer may change only fields in `TUNABLE_FIELDS`, within declared bounds. Anything else is rejected automatically.
- Decision records are immutable. Outcomes go to `trade_outcomes`, reviews to `trade_reviews`, linked by `decision_id`.
- Journal phase: first 100 closed trades per strategy version (a trade = one taken signal booked in both books, across all underlyings). Proposals and experiments are locked until exactly 100.
- Holdout: the chronologically last 30% of recorded trading days; the reviewer data loader filters it out at the query level; re-split only when a new version is adopted, and each split is recorded in the experiment.
- Gate (all required, per book): at least 30 holdout trades; net expectancy above current version after costs; profit factor at least the current one; max drawdown no worse than current + 10%; bootstrap 90% CI of the expectancy difference reported ("weak evidence" if it includes 0); beats random-entry baseline (same trade count and time-of-day distribution, same exits, 200 seeds, percentile reported) and "no trade". Running count of experiments tried is shown with every result.
- Footer: "Paper trading only. EOS/EOR are proxies. Results are not validated for live trading."
- Stop after each milestone with a summary and the test output.

## Review Focus

1. **Missing bid/ask, or a missed snapshot mid-trade:** the fill uses LTP plus fallback slippage, `fill_quality = ltp_fallback`; a gap during a trade closes it with `exit_reason = data_gap`; nothing is interpolated (Tasks 3, 6).
2. **Stop and target in the same minute:** the stop is booked (Task 3).
3. **Expiry day and last minutes:** time to expiry under a day, options near zero, a time exit at 15:15 before the recorder's 15:30; no entries when the chosen option has no bid and a fallback price below one tick (Tasks 3, 4).
4. **Holdout leakage through any path** (aggregates, reviews, experiment evidence), including a holdout row injected into the store (Task 8).
5. **LLM failure modes:** invalid JSON, a proposal touching a locked field, a proposal that is a no-op, the API key missing (reviewer skips and logs, the journal is unaffected) (Tasks 7, 9).
